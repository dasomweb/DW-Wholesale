# DW Wholesale 3.0 개발

> 작업 기준 문서. 운영자가 제시한 3.0 개발 지시서 원문을 그대로 보관합니다 (2026-11-10).
> 단계별 진행 상황과 결정 사항은 이 문서 끝의 "진행 기록"에 덧붙입니다.

이 저장소(dasomweb/DW-Wholesale, 구 dw-catalog-wp)는 DW Product Catalog와 DW Wholesale Customer Management를 통합한 워드프레스 플러그인 "DW Wholesale 3.0"의 기반이다. 첫 적용 사이트는 kgitrading.com(Sea JEM, 수산·일식 식자재 도매)이고, 다른 도매업체에도 설치할 수 있는 범용 제품으로 만든다.

시작 전에 docs/ARCHITECTURE.md, docs/SHORTCODES.md, docs/MIGRATION-PLAN.md, CHANGELOG.md를 읽고 기존 구조를 파악하라. 그다음 이 프롬프트 전체를 docs/V3-SPEC.md로 저장하고 작업 기준으로 삼아라.

## 지켜야 할 기준
- 기존 구조를 유지한다. 코어(core/)는 워드프레스 코드 없는 PHP, 워드프레스 연결은 includes/wp/.
- 내부 접두사 dwcat_ / DWCAT_와 테이블 이름 {prefix}dwcat_*는 유지한다. 새 테이블도 같은 규칙을 따른다.
- 텍스트 도메인은 dw-wholesale. 모든 화면 문구는 번역 함수로 감싼다.
- 보안: 모든 폼에 nonce와 권한 확인, 출력 이스케이프, 업로드 형식·용량 검사. 신청서 첨부파일은 공개 URL로 접근할 수 없게 한다.
- 화면: 흰 배경, 고딕 계열 폰트(Inter + Noto Sans KR), 카드형 구성. 관리자 화면은 워드프레스 관리자 안에 자연스럽게 들어가야 한다.
- PHP 7.4~8.3 지원, MySQL·MariaDB 지원.
- 단계마다 브랜치(v3/phase-N-이름)를 만들고 PR로 올린다. 기존 테스트를 모두 통과시키고, 새 기능에는 테스트를 추가하고, CHANGELOG의 [3.0.0] 항목에 기록한다.
- 각 단계가 끝나면 멈추고 무엇을 했는지, 무엇을 확인해야 하는지 보고한 뒤 다음 단계로 넘어가도 되는지 물어라.

## 범위 밖 (하지 말 것)
온라인 결제·장바구니·주문 처리(견적 요청만), WooCommerce 연동, 외부 회원 플러그인 연동(로그인은 자체 구현), Gutenberg 블록(위젯은 숏코드만), 모바일 앱.

## 현재 kgitrading.com 데이터 (마이그레이션 대상)
- 상품 439개(공개 428, 비공개·초안 11): 글 타입 product, 필드 dw_pc_product_name, dw_pc_item_code, dw_pc_pack_size_raw, dw_pc_brand_raw, dw_pc_origin_raw, dw_pc_status(active/inactive/out_of_stock/discontinued), dw_pc_internal_note, post_content, 대표 이미지(437개)
- 카테고리 product_category 67개, 상위·하위 구조 없음. 그룹(Fresh, Refrigerated, Dry Goods, Frozen, Hardware)은 페이지 5개의 Kadence Query Block 필터 설정에만 있음
- 신청서: DW WCM 테이블 kin_dw_wcm_applications(접두사는 사이트마다 다르므로 감지할 것) 10건 + 첨부파일
- 회원가입 사용자: DW Admin 플러그인이 user meta로 관리
- 품질 문제: Status 빈 값 131, Brand 빈 값 122, 품목코드 22162 중복 2건, URL에 "-1" 붙은 상품 41, 이미지 없음 2, 빈 카테고리 2
- 보안 문제: /wp-json/wp/v2/product로 누구나 전체 상품 조회 가능

## 모듈별 요구사항

### M1 마이그레이션 (필수)
1. 원본 자동 감지: DW Product Catalog, DW WCM 테이블, DW Admin 사용자
2. 필드 연결 화면: dw_pc_* → 새 필드(위 목록 순서대로). 관리자가 연결을 바꿀 수 있음. 내부 메모는 비공개 필드로
3. 카테고리 그룹 생성: Kadence 페이지의 필터 설정에서 그룹을 만들고, 어느 페이지에도 없는 카테고리는 "미분류"로 표시
4. 사전 점검(dry run): 쓰기 전에 건수와 문제를 보여주고 문제별 처리 방법을 선택(빈 상태 → Active/Hidden/그대로, 중복 코드 → 둘 다 두고 검토 표시/최신만, "-1" URL → 품목코드로 정리/그대로). 결과를 CSV로 내려받기
5. 실행: 50건씩 백그라운드, 진행률 표시, 중단 후 이어서 실행 가능, 다시 실행해도 중복 생성 없음. 이미지는 WebP 변환
6. 마무리: Kadence Query Block을 저장된 숏코드로 교체(미리보기 후), 옛 URL /product/{slug}/ → 새 URL 301, 공개 REST 차단, 기존 플러그인 비활성화 안내
7. 되돌리기: 마이그레이션이 만든 것만 삭제하고 Kadence 페이지 복원. 원본 데이터는 어떤 경우에도 수정·삭제하지 않음

### M2 상품·카테고리 관리 (기존 코드 보강)
- 대시보드: 상품·카테고리·신청서 건수, 데이터 품질 알림, 카탈로그 페이지 현황
- 상품 목록: 상태 탭(전체·Active·상태 없음·품절·숨김·검토 필요), 이름·코드·브랜드 검색, 그룹·카테고리·브랜드·이미지 필터, 일괄 작업(상태 변경, 카테고리 이동, 브랜드 지정, 선택 내보내기, 삭제)
- 상품 편집: 품목코드 중복 즉시 확인, 브랜드 자동완성, 가격 그룹별 가격·최소 주문량, 옵션(Variations) 표, 이미지, 내부 메모, 카드 미리보기, 옛 URL → 새 URL 표시
- 카테고리: 그룹 → 카테고리 2단(기존 드래그 앤 드롭 트리 활용)

### M3 거래처·신청서·로그인 (자체 구현)
- [dw_wholesale_apply] 신청서: 항목을 관리자가 편집, 파일 첨부, 동의 체크, 접수 안내 메일
- 신청서 관리: 상태(New·추가 정보 요청·승인·거절), 중복 신청 감지·합치기, 내부 메모, 활동 기록
- 승인: 가격 그룹 지정 → 계정 생성(또는 같은 이메일의 기존 사용자 연결) → 비밀번호 설정 메일(48시간 유효, 1회용)
- [dw_wholesale_login]: 로그인, 비밀번호 찾기, 비밀번호 설정, 선택적 로그인 링크. 5회 실패 시 15분 잠금, 가입 여부가 드러나지 않는 안내 문구
- [dw_wholesale_account]: 가격 그룹, 견적 요청 내역, 회사 정보, 비밀번호 변경, 로그아웃. 승인 대기자에게는 "검토 중" 안내
- 전용 역할 dw_wholesale_customer: wp-admin 접근 차단, 관리자 바 숨김
- [dw_wholesale_quote]: 승인 고객이 상품을 담아 견적 요청(결제 없음), 관리자에게 메일 알림

### M4 숏코드 위젯
- [dw_wholesale_catalog] 범위: 전체 / group="frozen,dry-goods" / categories="nori,wasabi,gari" / exclude="..."
- 저장형: 관리자에서 설정을 저장하면 [dw_wholesale_catalog id="frozen"]로 사용, 사용 중인 페이지 목록 표시
- 검색(크게·작게·숨김, 추천어)
- 필터: 카테고리(목록 안 검색), 브랜드(목록 안 검색), 원산지, 재고 있음, 최근 30일 신상품, 사진 있음. 건수 표시, 선택한 필터 칩·전체 해제, 값이 없는 필터는 자동 숨김, 필터 순서·위치(사이드바/상단) 설정
- 정렬: 이름 오름·내림, 품목코드 오름·내림, 브랜드, 최신순, 카테고리, 수동 순서. 기본 정렬 지정, 페이지당 24/48/96
- 검색·필터·정렬 상태를 URL에 반영(공유 시 같은 결과)
- 카드 표시 항목 선택(품목코드·팩 사이즈·브랜드·원산지·카테고리 배지·가격), 카드 클릭 시 사이드 드로어 또는 상품 페이지
- 기기별: 데스크톱 4열·사이드바 필터, 태블릿 3열·슬라이드 패널, 모바일 2열(또는 목록)·하단 시트·"더 보기". 열 수와 페이지당 개수는 기기별 설정
- [dw_wholesale_search]: 헤더용 검색창

### M5 디자인 설정
- 메인 색상, 테두리 색상, 버튼 스타일(채움·외곽선·연한 배경)
- 폰트 세트: Inter+Noto Sans KR, Noto Sans KR, IBM Plex Sans KR, 나눔고딕, 테마 폰트 따름. 글자 크기 S·M·L
- 모서리 둥글기(카드·버튼·입력창 각각), 카드 그림자 없음·연하게
- 데스크톱·태블릿·모바일 미리보기
- CSS 변수 묶음(프리셋)으로 저장, 위젯별 design="..."로 지정

### M6 필드 공개 범위
- 전체 켜기·끄기(기본 꺼짐). 꺼져 있으면 "누구나" 필드만 사이트에 나감
- 필드별 공개 대상: 누구나 · 로그인 사용자 · 승인 고객 · 특정 가격 그룹 · 직원 전용
- 권한 없을 때 대체 표시: "로그인하면 보기" 링크 · 숨김 · 직접 쓴 문구, 승인 대기자는 "검토 중"
- 서버에서 걸러서 보낸다: 권한 없는 사람에게는 페이지 소스·검색·필터·정렬·REST·CSV 어디에도 값이 없어야 함(기존 비공개 필드 차단 구조를 확장)
- 관리자 미리보기: 방문자·승인 대기·승인 고객·직원 시점

### M7 프리셋
- 프리셋 = 상품 필드, 옵션 컬럼, 카테고리 그룹, 필터·정렬, 신청서 항목, 가격 그룹, 필드 공개 범위, 디자인의 묶음
- 기본 제공 6종: 수산·일식 식자재, 뷰티서플라이, 주얼리, 청과, 식당용품·포장재, 일반 도매(기존 필드 프리셋을 확장)
- 설치 마법사 첫 단계에서 업종 선택. 운영 중에는 "없는 것만 추가" 또는 "설정 교체"(상품·거래처 데이터는 지우지 않음)
- 적용 전 변경 내용 미리보기, 적용할 때마다 복원 지점 저장
- 현재 설정 .json 내보내기·가져오기

### M8 권한별 메뉴 접근
- Access 화면(Administrator 전용): 역할 × 메뉴 표에서 숨김·보기·편집 지정. Administrator는 항상 전체 권한
- 기본값: Editor = 대시보드(보기), 상품·카테고리·거래처(편집) / Author = 대시보드·카테고리·거래처(보기), 상품(편집) / Contributor = 대시보드·상품(보기). 나머지 메뉴(필드, 가져오기·내보내기, 마이그레이션, 숏코드, 디자인, 프리셋, 설정)는 Administrator만
- 세부 동작 권한: 상품 삭제, 신청서 승인·거절, 가격 그룹 변경, 직원 전용 필드 보기, CSV 내보내기
- 운영자 모드: Editor 이하에게 워드프레스 외모·플러그인·도구 메뉴 숨김, 로그인 후 DW Wholesale 대시보드로 이동
- 숨긴 메뉴는 URL로 직접 들어와도 서버에서 차단

### M9 관리자 언어
- 관리자 화면 언어: English · 한국어 · 워드프레스 사용자 언어 따름. 상단 EN/한국어 버튼은 내 계정에만 적용
- 사이트 위젯 언어는 따로 설정, 버튼·안내 문구 직접 수정 가능
- .po/.mo로 관리, 한국어 번역 파일 포함

## 완료 기준
- 마이그레이션: 상품 439·카테고리 67·이미지 437·신청서 10건이 같은 건수로 옮겨짐(카테고리별 비교표), 선택한 처리 방법대로 결과가 나옴, 다시 실행해도 중복 없음, 되돌리기 후 원본 그대로, 옛 URL 301
- 위젯: 숏코드 하나로 단일 카테고리·그룹·여러 카테고리·전체 보기, 검색·필터·정렬을 함께 써도 결과 일치, 390·834·1440px에서 가로 스크롤 없음, 상품 수에 비례해 DB 조회가 늘지 않음
- 거래처·권한: 신청 → 승인 → 비밀번호 설정 → 로그인 → 가격 확인 → 견적 요청 동작, 홀세일 고객 wp-admin 차단, Editor는 운영 메뉴만 보이고 URL 직접 접근 차단, 권한 없는 사용자에게 보호 필드가 소스·REST·CSV 어디에도 없음, 관리자 화면 한/영 전환 시 빠진 문구 없음
- 품질: 기존 테스트 전부 통과 + 새 모듈 테스트, MySQL·MariaDB 실제 DB 테스트 통과
